# Контекст для Claude Code

Сайт клуба спортивной мафии «Триада Менделеева» (РХТУ). Исходный замысел — в [PLAN.md](PLAN.md),
установка на сервере — в [README.md](README.md). Здесь то, чего в них нет: как безопасно менять
код, какие решения уже приняты владельцем и где лежат грабли.

## Стек и деплой

* PHP 8.2 + MySQL (PDO), хостинг Beget. Тёмная тема, CSS-переменные `--bg/--sf/--tx/--ac`.
* DocumentRoot — `public_html/`. Ядро — `inc/` (`bootstrap.php`, `db.php`, `auth.php`, `helpers.php`,
  `layout.php`, `rating.php`, `elo.php`, `bot_lib.php`, `player_stats.php`).
* `config.php` лежит в корне репозитория (уровнем ВЫШЕ `public_html`) и **не** в git.
* Миграции — `db/migrations/NNN_*.sql`, применяются автоматически при деплое. Если в имени файла
  есть слово `recompute`, деплой дополнительно пересчитает рейтинги и ELO.
* **Пуш в `main` = мгновенный деплой на прод** (GitHub webhook → `public_html/deploy.php` →
  `git reset --hard` + миграции). Ветка `test` и домен `test.triada-mendeleeva.ru` существуют, но
  фактическая работа идёт прямо в `main` (README на этот счёт устарел).

## Как менять код, чтобы не уронить сайт

**На машине владельца нет ни `php`, ни `node`, ни Android SDK** (WSL не установлен, Java только JRE
без `javac`). Проверить синтаксис локально нечем, а деплой срабатывает сразу после пуша — опечатка
в `inc/bootstrap.php` или `inc/auth.php` положит **весь** сайт, потому что их подключает каждая
страница. Поэтому:

1. Правки PHP / JS / Java — сначала **в ветку**, не в `main`. `deploy.php` игнорирует все ref, кроме
   `deploy_branch`, так что ветка на прод не уезжает (проверено).
2. Дождаться зелёных CI-гейтов, затем `git checkout main && git merge --ff-only <ветка> && git push`.
3. Гейты в `.github/workflows/`:
   * `php-lint.yml` — `php -l` (PHP 8.2, как на Beget) по всем файлам **и** `node --check` по
     `public_html/assets/js/*.js`; на всех ветках;
   * `build-apk.yml` → job `compile-check` — `assembleDebug` (автоключ Android, секреты не нужны):
     ловит ошибки компиляции, даже пока релизный ключ не настроен;
   * `build-apk.yml` → job `gate` — если секрета `ANDROID_KEYSTORE_B64` нет, подписанная сборка
     **пропускается**, а не падает (иначе владельцу летят письма «Run failed» на каждый пуш).
4. Результат CI смотреть по **полному** SHA: `api.github.com/repos/BahtukOnce/triada-mendeleeva/actions/runs?head_sha=<40 символов>`.
   Короткий SHA фильтр не находит. Логи job'ов через API отдают 403 — читать в браузере.
5. При правках `style.css` или `app.js` — поднять `?v=N` в `inc/layout.php`.
6. **Репдев:** над репозиторием параллельно работает второй разработчик. Перед каждым пушем
   `git fetch origin main && git pull --ff-only`. Если `--ff-only` не проходит — не форсить, а
   перенести свои коммиты поверх свежего `origin/main`. Никогда не `push --force` по `main`.

## Решения владельца — это НЕ баги, не «исправлять»

* «Фото» и «Тесты» временно убраны из меню (страницы живы, вернуть = раскомментировать в `nav_items()`).
* Список игроков: по умолчанию «Активные» (играли за 12 мес) + тумблер «Все · N».
* Единая регистрация: `/register.php` → `/join.php`; **пароль задаётся сразу в заявке** (хеш в
  `club_applications.password_hash`), приём заявки создаёт аккаунт. `/activate.php` — фолбэк для
  старых заявок без пароля.
* Разделение «член клуба / просто игрок» **отклонено**: все игроки в одной базе.
* Рейтинг клуба = игровые вечера (турниры видны в профиле и списках, но не в основном рейтинге).
* Легаси-рейтинги с mafiauniverse заморожены (`is_frozen`) и не пересчитываются.
* `Ci`: при победе чёрных даётся полностью, при победе красных — половина. Большой техфол −0.6
  (максимум 2). ЛХ у `lh_seat`.
* Уведомления о заявках: колокольчик админам + руководителю, Telegram-бот — только руководителю.
* ELO-константы приняты (K=310, делители 2500/900, база 0.35, множитель проигрыша 0.6, пол 100);
  объяснялка формулы — на `rating.php` (сворачиваемый блок, id `elo`).
* Каспер (player id 393) — призрак-пасхалка. Слияния игроков — **только с разрешения владельца**:
  одинаковый ник ≠ один человек.

## Грабли в данных

* **Легаси-вечера лежат как обычные `game_days` без флага**, а из клубного рейтинга исключены ИМЕННО
  отсутствием строки в `rating_days` (см. комментарий в `inc/legacy_import.php`). Поэтому «привязать
  все непривязанные дни» = влить сезоны 2022/23–2024/25 в текущий рейтинг. Любой бэкофилл —
  только с границей сезона (см. миграцию `077_recompute_attach_site_days.sql`).
* Вечера, созданные на сайте, теперь привязываются к рейтингу автоматически —
  `day_attach_to_main_rating()` вызывается при создании вечера и при сохранении игры.
* Сезон = 1 сентября — 31 августа, `current_season_bounds()`. Сезонный рейтинг ищется по **строке**
  названия («Сезон 2025/2026») — 1 сентября 2026 лукап промахнётся, если рейтинг не переименовать
  (известная мина, в плане исправлений).
* Ачивки считаются за всю историю клуба; `dop30`, `don`, `danger` раньше брались из сезонного
  `rating_cache` — исправлено. Но «Больше всех допов» и «Больше всех ПУ» в блоке «Рекорды клуба»
  всё ещё сезонные.
* ELO в таблицах вечера и турнира — **по итогам события** (`event_exit_elo`), не входной и не текущий.
* Ключ подписи APK утёк в публичный репозиторий; CI переведён на GitHub Secrets, **ротация ключа —
  за владельцем** (инструкция в `mobile/KEYSTORE.md`). Репозиторий приватным делать НЕ надо:
  `app/download.php` и `app/version.php` завязаны на публичные ссылки GitHub Releases.

## Открытые задачи

1. **Ротация ключа подписи APK** + 4 секрета в GitHub → без этого приложение не пересобрать
   (в нём ждут фирменные диалоги обновления, «что нового» на экране загрузки и фикс разрешения
   на установку). Инструкция — `mobile/KEYSTORE.md`.
2. **Крон импорта заявок** из старой Google-формы: `0 */6 * * *` → `php public_html/import_applications.php`.
   Код готов и проверен, baseline выставлен; нужен только сам крон в панели Beget.
3. **План исправлений v2** — 64 задачи в 7 блоках после аудита и пересверки:
   https://claude.ai/code/artifact/a60273a7-5e29-4d92-93a4-963e46ce9bd4
   Из незаблокированного осталось: `sitemap.php` (SQL-ошибка съедает все профили/турниры/вечера),
   soft-404 на `player/tournament/day`, легаси-дубль `vs.php`, `flock` + UNIQUE в импорте заявок,
   валидация загружаемых кропов. 12 задач ждут решений владельца.
4. Проверить, **держится ли вход** после правок сессий (`session_regenerate_id` в авто-входе по
   remember-куке + `session.use_strict_mode=1`). Если нет — откатить эти два места.

## Что сделано в последней сессии (июль 2026)

Безопасность: закрыта эскалация до руководителя через сброс пароля (пароль верхушки больше не
печатается сбрасывающему); `remember_revoke_all()` отзывает 400-дневные токены при любой смене
пароля, понижении роли и удалении аккаунта; вебхук бота стал fail-closed; админ-права бота только
по `users.role`; манифест обновлений ушёл из общей `/tmp` в `storage/` + двойная валидация URL APK.

Рейтинг и статистика: вечера с сайта попадают в клубный рейтинг; ачивки `dop30`/`don`/`danger`
переведены на всю историю (получателей стало 6/20/12 вместо 1/10/8); новая ачивка «🔮 Чуйка»
(за чёрных 3+ раза шериф убит первой ночью); ELO в таблицах — по итогам события.

Интерфейс: «Лучшие дуэты» — таблица с сезонами и порогом от 5 совместных игр; «Битва факультетов» —
сезоны, состав по наведению, «Другое» исключено, пометка «вне зачёта»; блок ЛХ показывается всегда
(пустой = «промах»); выбор игрока в «Дуэли» — выпадашка с поиском (раньше поиск не работал нигде
из-за раннего `return` в новостном блоке `app.js`); фирменные диалоги обновления в приложении.
